# 合成气声测试集 · 评测

2026-11-19 ｜ 用百炼的语音模型造「气声」音频，看它能不能当 ASR 的评测/增强数据

## 0. 一句话

调通了「百炼 token-plan 网关 → `qwen-audio-3.0-tts-plus` → 气声化」这条链路，生成 50 句合成气声；
评测结果是 **合成气声 CER 18.2%，真实气声 69.6%（48 条有效录音）**。结论：**气声本身不是 whisper 的
主要障碍，真实录音的信号质量才是**——所以下一步优先修麦克风/电平，而不是立刻微调模型。

## 1. 为什么要合成

真实气声只有 50 句（`bench/`），每句都要人重录；改一版预处理就要重录一轮不现实。
合成气声的价值不是「替代真实基线」，而是：

- 有一个**可控变量**的测试集：同一批句子，只变「有没有基频」这一个因素；
- 能每天跑回归，不用等录音；
- 能当微调时的数据增强（同一句话 × 多种音色/语速/气声强度）。

## 2. 调通 API：它和文档里写的不一样

网关：`token-plan.cn-beijing.maas.aliyuncs.com`（DSH 里配的百炼额度通道），一个 key 就能用。
`/compatible-mode/v1/chat/completions` 的 OpenAI 兼容写法**调不通 TTS**（语音列表对不上，报
`Request voice is invalid!`），要改用 DashScope 原生 WebSocket 推理协议：

```
wss://token-plan.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference
run-task  → task-started → 二进制音频帧 → result-generated ×N → task-finished
```

关键参数（都试出来的）：

| 项 | 值 | 备注 |
|---|---|---|
| model | `qwen-audio-3.0-tts-plus` | `/models` 里可见的语音模型之一 |
| voice | `longanqian` | 只有这个音色可用；`Cherry`/`longxiaochun` 等全部 `task-failed` |
| format / sample_rate | `wav` / 24000 | 直接回 RIFF 头 |
| `instruction` | 「耳语，只用气流，声带不要振动」 | **这个字段有效**，能把 HNR 从 6.4dB 压到 2.5dB |

另外网关里还有 `qwen-audio-3.0-asr-flash`（识别）和 `qwen-audio-3.0-realtime-plus`（实时语音对话，
默认音色也是 `longanqian`），以后可以拿来对比。

## 3. 为什么还要「气声化」

实测指令只能让 TTS 变「轻声」，变不出真气声：

| 版本 | HNR（谐噪比） | 有声帧比例 | RMS |
|---|---|---|---|
| TTS 正常 | 6.4 dB | 25% | −19 dBFS |
| TTS + 耳语指令 | 2.5 dB | 12% | −25 dBFS |
| **真实气声** | **−5 dB** | **0%** | −20 ~ −35 dBFS |

所以补一步 DSP 气声化（`tools/synth_whisper.py: whisperize()`）：

1. STFT → 对数幅度 → 倒谱；
2. 把高倒频（对应基频与谐波）清零，只留频谱包络（约 2.2ms 以内）；
3. 用随机相位噪声乘上包络重合成；
4. 反 STFT + 重叠相加。

结果是「保留共振峰（能听懂）+ 去掉基频（是真气声）」。50 句合成后中位 HNR **−4.6dB**、有声帧 **0%**，
与真实气声的声学特征对齐。频谱对比见 [spectrogram_合成气声.png](spectrogram_合成气声.png)：

- TTS 正常：清晰的谐波条纹；
- TTS 轻声：条纹还在（所以指令不够）；
- TTS + 气声化：条纹消失，只剩噪声状能量——和真实气声是同一类纹理（真实录音的语谱只在本机比对，不进仓库）。

## 4. 评测结果（faster-whisper small，cpu/int8，同一批句子）

同一批前 20 句做消融，排除句子难度差异：

| 版本 | 有声帧 | HNR | CER |
|---|---|---|---|
| TTS 正常朗读 | 25% | 6.4 dB | 4.7% |
| TTS 轻声（指令） | 9% | 1.1 dB | 3.6% |
| **TTS + 气声化** | **0%** | **−4.6 dB** | **8.6%** |
| **真实气声** | **0%** | **−5 dB** | **61.3%** |

全量 50 句：

| 数据 | 句数 | CER | 日常 | DSH | 人名地名 | 数字标点 |
|---|---|---|---|---|---|---|
| 合成气声 | 50 | **18.2%** | 3.1% | 18.3% | 20.7% | 32.9% |
| 真实气声 | 50（48 有效） | **69.6%** | 45.7% | 69.2% | 77.1% | 89.6% |

两个可以直接拿来决策的结论：

1. **只去掉基频，CER 从 4.7% 涨到 8.6%**——气声本身对 whisper 是「有点难」，不是「根本不行」。
   真实数据里剩下的 ~53 个百分点，来自信号质量与真实说话方式，不是「没有基频」这一件事。
2. **四类的难度排序在合成集和真实集里完全一致**（日常 < DSH < 人名地名 < 数字标点）。
   说明合成集可以当**相对比较**的测试床（A/B 预处理、换模型、改 prompt 都行），
   但不能拿它的绝对 CER 当验收线。

另外体检了真实录音：50 条里有 2 条（001/002）是**纯静音**（RMS −120dBFS），其余 48 条都是
标准气声（HNR −3.5 ~ −6.1dB，有声帧 0%）。所以 70% 的基线是真实难度，不是录音事故；
但静音那 2 条也说明当时的采集链路不稳（BY-V20 全零问题）。

## 5. 建议的下一步（按性价比）

1. **先修信号质量**：现在 `prepare()` 已有 60Hz 高通 + VAD + 归一化到 −20dBFS。可以加
   （a）轻度谱减降噪；（b）气声专用的低频补偿（气声低频弱，但 ASR 的声学模型是按正常语音训练的）。
   用合成集做 A/B 判断「有没有把无基频语音弄坏」，再用真实集看绝对值。
2. **换模型/提示对照**：`small` → `medium`（CPU RTF 约 1.2，50 句约 3 分钟，可以接受）；
   `initial_prompt` 里加领域词。
3. **合成集做数据增强**：同一句 × 多种音色/语速/气声强度，用于后续微调；现在只有 1 个音色，
   要扩就先解决音色问题（或做音色迁移）。
4. **验一下 API 的 ASR**：网关里还有 `qwen-audio-3.0-asr-flash`，但试了
   `/audio/transcriptions`（404）和 chat 里塞音频（400）都没调通；实时会话里它的输入转写默认用
   `fun-asr`。如果能把 asr-flash 调出来，值得和 whisper 做一次同条件对照。

## 6. 复现

```bash
cd whisper-type

# 造 50 句合成气声（约 2 分钟，需要百炼 key）
python tools/synth_whisper.py --out bench-synth

# 只跑 10 句 / 只要轻声 / 不气声化
python tools/synth_whisper.py --limit 10
python tools/synth_whisper.py --mode soft --out bench-synth-soft
python tools/synth_whisper.py --mode normal --out bench-synth-normal

# 评测（和真实 bench 同一套脚本）
python tools/benchmark.py --dir bench-synth
```

产物：`bench-synth/*.wav`、`bench-synth/synth_meta.json`（每句的 HNR、有声帧、时长）、
`docs/bench_report_bench-synth.md`、`docs/spectrogram_气声对比.png`。

## 7. 局限（别当成答案）

- 合成气声来自 TTS 的**正常朗读**再气声化，辅音过渡比真人气声干净，所以它**偏简单**（11～18% vs 50%）；
- 只有 1 个音色，说话人多样性为 0；
- 没有真实房间噪声/混响/麦克风频响；
- 不能替代真实基线，只能做相对比较和数据增强。

## 8. 用真实录音校准（2026-11-20 追加）

想让它更像真实录音：`tools/synth_calibrated.py` 拿 `bench/` 的真实气声当参考，逐条对齐：

1. **频谱形状**：按 1/3 倍频程平滑后的长期平均谱（LTAS）做 EQ，增益限制 ±12dB；
2. **底噪**：从真实录音的停顿段估噪声谱，按真实信噪比（实测中位 **43dB**，房间很干净）混入；
3. **电平/动态**：拉到真实录音的语音 RMS 中位数。

结果——**没有变难**：

| 数据 | whisper small | SenseVoice |
|---|---|---|
| 合成气声（未校准） | 18.2% | 11.5% |
| 合成气声（校准后） | 18.0% | 11.3% |
| 真实气声 | 69.6% | 48.0% |

说明真实录音的难度**不在频响和底噪**（这个房间 SNR 43dB，很干净），而在真人气声本身：
辅音能量弱、口型/发音不确定、节奏与 TTS 不同。所以：

- 合成集可以继续用来做**相对比较**（换引擎、改参数、A/B 前后谁更好）；
- 但**绝对 CER 必须用真机录音**——这也是为什么下一步要按 `docs/测试方案.md` 去手机录音；
- 校准工具留着：等有了嘈杂环境/不同设备的录音，再用那份数据校准，合成集才有机会接近真机难度。

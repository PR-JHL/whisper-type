# 真机测试方案（手机录音 → 本机评测）

2026-11-20 ｜ 给「办公室没法实测，换到别处用手机自己说」准备

## 0. 要回答的三个问题

1. **三种发声方式差多少**：气声 / 低声 / 正常音量，同一批句子上的 CER 和延迟；
2. **引擎怎么选**：`sensevoice`（默认，气声上 CER 50.1%）vs `whisper small`（70.8%），
   在正常/低声上是不是也一样；
3. **能不能日常用**：P0 验收是「日常句 CER ≤10%、单句 ≤1.5s」——先看真实差距有多大。

## 1. 录什么

语料就是 `data/bench_zh.tsv` 里的 50 句（日常 15 / DSH 15 / 人名地名 10 / 数字标点 10），
**同一批句子录三种模式**，这样三种模式之间、和已有基线之间都能直接比：

| 模式 | 文件名前缀 | 怎么念 |
|---|---|---|
| 气声 | `whisper-` | 只出气、声带不振动（就是现在 `bench/` 的录法） |
| 低声 | `low-` | 很小声，但正常出声带振动（能听到嗓子） |
| 正常 | `normal-` | 正常音量，像打电话 |

- **完整版**：3 × 50 = 150 段，约 40–50 分钟（中间可停，文件按句存）；
- **快速版**（先跑通链路）：每种模式 15 句（001–015）= 45 段，约 12 分钟；
- 建议先快速版，链路走通再补全量。

## 2. 怎么录（这几条直接影响结果）

1. **离嘴 3–5cm**，手机/领夹麦固定住，别手持晃；
2. **关掉手机录音 App 的降噪/增强/自动增益**（会把气声当噪声削掉）；
   `record_phone.html` 页已经关掉 `noiseSuppression / echoCancellation / autoGainControl`；
3. **安静房间**，但不用绝对静音；录之前空录 **5–10 秒环境噪声**（存成 `noise.wav`），
   用来估计噪声底；
4. 一句 **1–4 秒**，别刻意放慢；念错就重录这一句，别剪接；
5. 三种模式**同一设备、同一位置、同一天**录完，避免设备/位置变化混进来；
6. 手机系统自带的「语音备忘录」也可以，但注意别开「语音增强」。

## 3. 手机端录音页

已经生成好了：[record_phone.html](record_phone.html)

- 把仓库拉下来/把文件传到手机，用手机浏览器打开（Chrome / Safari 新版）；
  需要 **https 或 localhost** 才能用麦克风——最省事的办法：电脑上 `python -m http.server 8000`，
  手机连同一个 WiFi 访问 `http://<电脑IP>:8000/docs/record_phone.html`
  （普通 http 访问局域网 IP 在部分浏览器会被拦；被拦就用系统录音机，按 `<mode>-<id>` 命名）；
- 页面自带 50 句和三种模式：选模式 → 按录音 → 停止 → 「下载这段」→ 「下一句」；
- 每段文件名是 `<mode>-<id>.webm`（iPhone 一般是 `.m4a`），传到电脑放同一个文件夹即可。

不想用网页也行：系统录音机录，**按 `<mode>-<id>` 命名**（例如 `whisper-003.m4a`），
`whisper`/`气声`、`low`/`低声`、`normal`/`正常` 这些写法导入脚本都认。

## 4. 传回电脑、整理

```bash
cd whisper-type
python tools/import_recordings.py --src "D:\\手机录音"
```

它会：

- 用 ffmpeg 统一转成 **16k 单声道 WAV**；
- 按模式分到 `bench-modes-whisper/`、`bench-modes-low/`、`bench-modes-normal/`；
- 逐句体检（时长、电平、是否静音/太小）并提示缺了哪些句子；
- 写 `docs/recordings_manifest.json`（模式/句子/时长/电平/参考文本）。

**这些录音不提交**：`.gitignore` 里 `bench*` 已覆盖，只留在本机。

## 5. 评测

```bash
# 三种模式各跑一遍（默认引擎 sensevoice；想比较 whisper 就加 --engine whisper）
python tools/benchmark.py --dir bench-modes-whisper
python tools/benchmark.py --dir bench-modes-low
python tools/benchmark.py --dir bench-modes-normal

# 想三种模式放一张表里对比
python tools/compare_modes.py            # 汇总 docs/bench_result_bench-modes-*.json
```

（`compare_modes.py` 见下一节；没生成就是还没跑过任何模式。）

产出：`docs/bench_report_bench-modes-<mode>[_sensevoice].md`，含总体 CER、分类 CER、
逐句参考/识别/耗时（延迟 = `elapsed`，RTF = `elapsed/duration`）。

## 6. 结果怎么判

| 指标 | 看什么 | 参考 |
|---|---|---|
| 总体 CER | 三种模式的差距 | 现有气声基线：sensevoice 48.0%（48 句有效） |
| 分类 CER | 数字标点/人名地名最容易崩 | 气声 50.1% 时：数字标点 65.6%、日常 41.6% |
| 延迟 | 单句耗时、RTF | sensevoice ≈ 0.05s/句（RTF 0.04）；whisper small ≈ 2.7s/句 |
| 静音幻觉 | 空录/噪声输入必须出空 | 现有过滤逻辑应保证 0 次 |

判据（和 `docs/需求梳理.md` 一致）：

- P0：日常句 CER ≤ 10%、单句 ≤ 1.5s。**现在离 10% 还差很远**（气声 40%+），
  所以这一轮先把「三种模式的真实差距」和「引擎选择」定下来；
- 如果正常/低声 CER 也高 → 问题在引擎/环境，不只在气声；
- 如果只有气声高 → 再决定是调模型、采集质量，还是接受「气声 + 词库/纠错」的路线。

## 7. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 录音没有声音 / 电平很低 | 手机孔/麦克风被挡住；录前用页面试录一段看波形；低于 −45dBFS 导入时会有提醒 |
| iPhone 文件是 `.m4a` | 正常，导入脚本用 ffmpeg 转 |
| 网页打不开麦克风 | 需要 https/localhost；换 Chrome；或直接用系统录音机 |
| 气声被手机「优化」掉了 | 关掉降噪/增强/自动增益；iPhone 用「语音备忘录」原声 |
| 文件名不对 | 必须 `<mode>-<id>`，如 `whisper-003.m4a`；`气声-003` 也认 |
| 三种模式录的时候句子顺序不一致 | 没关系，按文件名里的 id 对，不靠顺序 |

## 8. 这一轮结束要交回什么

1. `bench-modes-{whisper,low,normal}/` 三份录音 + `docs/recordings_manifest.json`；
2. 三份 `bench_report_*.md`；
3. `noise.wav`（空录的环境噪声）——后面做降噪/校准要用。

拿到这些，就能把「气声 vs 低声 vs 正常」的真实差距、引擎选择、以及要不要继续投入
都定量下来；在此之前，可以先在合成校准集上迭代（见 `docs/合成气声_评测.md`）。

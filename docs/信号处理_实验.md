# 气声信号处理实验

2026-11-20 ｜ faster-whisper `small` / `cpu int8` ｜ 真实气声前 20 句（003–022，跳过 001/002 静音）

## 想回答什么

真实气声 CER 70%，合成气声只有 18%。差的这 50 个百分点里，有没有「廉价预处理」能救的部分？
试了四种不改模型的手段（都作用在 `prepare()` 之后：16k、60Hz 高通、VAD 裁首尾、归一化 −20dBFS）：

| 变体 | 做法 |
|---|---|
| `base` | 现有流程 |
| `denoise` | 谱减降噪（噪声底取低能量帧的中位数） |
| `tilt` | 低频补偿：900Hz 以下 +6dB（气声缺低频，whisper 按正常语音训练） |
| `compress` | 动态范围压缩（把弱辅音抬起来） |
| `prompt` | 音频不动，`initial_prompt` 换成「以下是气声普通话，请转写」 |

## 结果 1：五种手段，20 句

| 变体 | CER |
|---|---|
| base | 58.2% |
| denoise | 59.3% |
| **tilt** | **55.8%** |
| denoise_tilt | 56.1% |
| compress | 57.5% |
| prompt | 60.0% |

## 结果 2：低频补偿给多强合适

| 变体 | CER |
|---|---|
| base | 57.5% |
| **tilt（+6dB @900Hz）** | **55.8%** |
| tilt9（+9dB） | 57.5% |
| tilt12（+12dB） | 56.8% |
| tilt_compress | 59.0% |

## 结论（说实话的那种）

1. **只有低频补偿（+6dB 以下）方向是对的**，但收益约 **1.7 个百分点**；
2. 降噪、动态压缩、气声 prompt 都不起作用，甚至更差——说明瓶颈不在「噪声」和「模型不知道这是气声」；
3. **这 1.7 个点要打折看**：whisper 带温度回退，同一份音频两次跑 CER 能差 ~1 个点（base 两次分别是
   58.2% 和 57.5%）。所以 <2 个点的差异不要当成真提升，要换全量 48 句 + 多次平均才算数；
4. 预处理不是主战场。按性价比，下一步应该先看**采集质量**（电平/麦克风/离嘴距离）和**换模型**
   （`medium` / `large-v3`），再考虑微调。

## 复现

```bash
cd whisper-type
python tools/exp_preprocess.py --dirs bench --limit 22 --skip 001,002 \
    --variants base,denoise,tilt,denoise_tilt,compress,prompt
python tools/exp_preprocess.py --dirs bench --limit 22 --skip 001,002 \
    --variants base,tilt,tilt9,tilt12,tilt_compress
```

指标：CER（字符错误率），与 `docs/bench_report.md` 同一套 `metrics.report()`。

# 气声输入 · 需求梳理（待确认）

版本 0.1 ｜ 2026-11-19 ｜ 状态：等你确认后开工

---

## 0. 一句话

把「气声说一句 → 准确变成文字」做成一个**可靠的识别引擎**：先接进 DSH 对话框日常用，
准确率达标后再做成 Windows 输入法级工具，并用个人词库解决专有词和个性化。

---

## 1. 现状与差距

| 已有 | 缺什么 | 影响 |
|---|---|---|
| 录音 → faster-whisper → 文字注入，端到端能跑 | 只在标准朗读（TTS）上验过 CER 0% | **真实气声的准确率完全未知**，这是最大风险 |
| 29 个单元测试、模型本地缓存、幻觉过滤 | 没有固定测试集和评测脚本 | 改一个参数不知道是变好还是变坏 |
| CPU 上 small 模型约 1.5s/句（固定开销） | 延迟还没优化，流式也没有 | 连续输入会打断思路 |
| 独立程序 + 全局热键 + SendInput | **不是 DSH 插件**，只是往焦点窗口打字 | 焦点、权限、热键冲突都不可控 |
| 无词库 | 人名、项目名、术语全靠模型猜 | 专有词几乎必错 |

> 术语澄清：现在交付的是独立程序 `whisper-type`，不是 DSH 插件。
> 「接进 DSH」是本期 P0 的一部分，需要新写客户端插件 + 本地服务。

## 2. 目标与优先级

| 优先级 | 目标 | 判断标准 |
|---|---|---|
| **P0** | 气声识别在你自己的语料上「够用」，并能在 DSH 里顺手用 | 日常句 CER ≤ 10%，DSH 里说完就出字 |
| **P1** | 个人词库与专有词纠错 | 你的常用人名/术语召回 ≥ 90% |
| **P2** | Windows 输入法级工具 | 任何输入框都能用，稳定常驻 |
| P3（远期） | 真正的 TSF 输入法 / 多用户 | 视 P2 使用情况再定 |

## 3. 用户与场景

- **用户**：先按单用户（你）设计，架构上不排除多用户，但不做账号体系。
- **环境**：办公室 / 宿舍 / 夜里，安静但不绝对静音；领夹麦离嘴 3–5cm。
- **典型输入**：1–4 秒的短句，一次一句；DSH 聊天、提问、写代码注释、记待办。
- **不包含**：会议转写、多人对话分离、长文听写、移动端。

---

## 4. 范围

**做：**

- 气声中文识别引擎（本地，可离线）
- DSH 内「按住说话 / 点一下说话」输入
- 个人词库（导入、管理、生效）
- 准确率与延迟的评测工具、回归基线
- 可选的 LLM 文本纠错（默认关）

**不做（本期）：**

- 实时字幕、会议记录、说话人分离
- 抓取或分发搜狗/QQ 的受版权词库
- 真正的 TSF 输入法（P2 只做可行性预研）
- 多语言（先中文，英文/数字混说支持）

## 5. 功能需求

### P0-1 识别质量

- 按住说话（PTT），松开出整句；支持「按一下开始/再按结束」。
- 气声、小声、正常音量都能用（自动增益 + 电平提示）。
- 简体中文 + 标点；中英混说、数字、常见符号。
- 静音或纯噪声**不得输出任何字**（现在已验证：静音返回「没听到说话」）。
- 识别失败/明显错时，一键重说，不用重开程序。
- 可选「候选/纠错」：对低置信度结果给出 2–3 个候选让你点选（P1）。

### P0-2 DSH 集成

两个方案，建议先 A 后 B：

**方案 A（推荐，需技术验证）**：DSH 客户端插件 + 本地 ASR 服务

```
浏览器麦克风 (Web Audio) → WebSocket → 本地 Python 服务 (faster-whisper)
        ↑                                      ↓
   DSH 输入框 ←──────── 文本 ────────────────┘
```

- 输入框旁一个麦克风按钮 + 一个快捷键；说完文字直接进输入框，不模拟键盘。
- 优点：焦点稳、无全局钩子、不用管理员权限、体验原生。
- 待验证：DSH 客户端插件能否拿到输入框 Slot、能否申请麦克风权限、本地 WS 端口策略。

**方案 B（过渡，现在就能用）**：独立程序 + 全局热键 + SendInput

- 优点：任何窗口都能用；缺点：热键冲突、焦点窗口权限、看不到状态。
- 作为 A 没跑通前的兜底，保留。

### P0-3 评测与回归

- 固定测试集：50–100 句，分四类——日常、DSH/编程、人名地名、数字标点。
- 指标：CER、专有词召回、延迟 P50/P95、静音幻觉次数。
- 每次改动用同一套跑 A/B，结果存档。

### P1-1 个人词库

- **导入**：你自己的搜狗/QQ 用户词导出文件、术语表、项目文档、通讯录（需你授权）。
- **生效方式**：
  1. 解码前：把高频词作为 hotwords / initial_prompt 偏置；
  2. 解码后：按拼音做同音纠错（`jintian` → 今天/金田，按词库选）；
  3. LLM 纠错时把词库作为术语表传给模型。
- **管理**：增删改、启用开关、按场景分组（DSH/工作/生活）。
- **合规**：只处理你本人导出/授权的内容，不抓取、不分发第三方词库。

### P1-2 个性化

- 从你的历史输入里学常用词和句式（本地，可关）。
- 场景包：DSH、编程、工作、生活，各自一套 hotwords。

### P2 Windows 输入法级

两种形态，成本差 5–10 倍：

| 形态 | 做法 | 成本 | 体验 |
|---|---|---|---|
| 后台常驻工具（讯飞式） | 全局热键 + 注入/剪贴板 | 低（1–2 周） | 够用，但候选框要自己做 |
| 真正的 TSF 输入法 | C++ COM 文本服务 | 高（1–3 个月） | 原生候选、任何输入框 |

建议：**先做后台常驻工具**；TSF 只在「必须原生候选」时才评估。

## 6. 准确率工程（核心工作）

按「投入产出比」排序，每一档都要先用测试集量化：

| # | 手段 | 预期收益 | 成本 | 备注 |
|---|---|---|---|---|
| 1 | 麦克风位置/电平/关降噪 | 大 | 低 | 已完成一半，需实测 |
| 2 | 模型 small → medium | 中 | 中 | CPU 延迟会翻倍，需权衡 |
| 3 | 气声前端：频谱倾斜补偿、VAD、轻降噪 | 中 | 中 | 气声低频弱，需要实验 |
| 4 | 解码偏置：hotwords / prompt / beam | 小–中 | 低 | 专有词立竿见影 |
| 5 | 个人词库同音纠错 | **专有词大** | 低 | 拼音编辑距离 + 词频 |
| 6 | LLM 上下文纠错 | 中–大 | 低 | 只发文本；需你同意 |
| 7 | 用你的气声录音微调（LoRA/全量 small） | **大** | 高 | 需要 1–3 小时标注语料 |
| 8 | 置信度 + 重说/候选交互 | 中 | 低 | 比硬猜更可靠 |

**关键判断**：Whisper 对气声有天然损失（气声缺基频、辅音弱）。
先测真实基线；如果 CER 卡在 20% 以上，第 7 项（微调）才是决定性的，
否则优先做 1/4/5/6，性价比最高。

---

## 7. 数据与隐私

- 音频默认只在内存，不落盘、不上传。
- 测试语料存本地，可随时删；录音前明确告知。
- LLM 纠错只发送识别后的**文本**，默认关闭；可强制「全本地」模式。
- 词库只存本地，不上传。

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 气声信息损失，CER 卡在 15–20% | 达不到「顺手」 | 早测基线；必要时微调；接受「短句+个人词库」定位 |
| 微调缺语料 | 无法做领域适配 | 你每天录 10 分钟，两周可攒 2 小时 |
| DSH 插件 API 不支持输入框/麦克风 | 方案 A 落空 | 先做技术验证；B 兜底 |
| 搜狗/QQ 词库不可导出/有版权 | P1 受阻 | 只用你本人导出的用户词 + 文档提取 |
| CPU 延迟 | 打断输入节奏 | medium 换 small、流式、GPU（待验证） |
| 单人过拟合 | 换人/换场景就崩 | 指标分场景；保留通用测试集 |

## 11. 待确认（回复编号即可）

1. **主战场**：只在 DSH 对话框用，还是任何 Windows 窗口都要？
   - 推荐：先 DSH，Windows 放 P2。
2. **延迟**：单句 1.0s / 1.5s / 2.0s，哪个可接受？
   - 推荐：P0 按 1.5s，P1 冲 1.0s。
3. **准确率**：日常句 CER 10% 算「能用」吗？专有词是否必须全对？
   - 推荐：日常 10%，专有词靠词库做到 90%+。
4. **测试语料**：愿不愿意录 50–100 句气声（每句 3–5 秒，约 30 分钟）？
   - 推荐：愿意，这是所有优化的前提。
5. **LLM 纠错**：允许把**文本**发到云端（DeepSeek）纠错吗？还是必须全本地？
   - 推荐：允许，默认关，可一键切全本地。
6. **词库**：你能导出搜狗/QQ 的「用户词」吗？是否授权从你的文档/聊天记录里提取术语？
   - 推荐：先用你手动整理的 50–200 个词起步。
7. **Windows 阶段**：后台常驻工具就够，还是必须要真正的输入法（候选框/任何输入框）？
   - 推荐：先后台工具，TSF 预研。
8. **用户数**：只你一个人用，还是以后给别人用？
   - 推荐：先单人，架构不锁死。
